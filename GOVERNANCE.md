# Governance

## Maintainers

The repository maintainer is responsible for the product direction, releases, access, and final decisions on changes. The project does not currently have a formal council, voting process, or release schedule.

## How changes are made

Contributors propose changes through pull requests. A maintainer reviews the change for student value, historical accuracy, accessibility, reliability, and fit with the project's scope. Reviews may request revisions or decline a change with a short explanation when practical.

Large changes to curriculum coverage, save formats, historical interpretation, or public interfaces should be discussed in an issue before implementation. Small corrections and focused bug fixes can be submitted directly.

## Releases and project policy

There is no fixed release cadence. The maintainer chooses when a change is ready for the default branch and when to publish a release. Security reports and conduct concerns follow [SECURITY.md](SECURITY.md) and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
